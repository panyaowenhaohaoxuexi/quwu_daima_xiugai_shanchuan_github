# 雾气感知、物理遮蔽 GT 监督的 RGB--TIR 去雾：更新方案

> 状态：核心方案已确定，尚未开始新主模型实现；加雾数据会同步生成物理补全掩码 `mask_GT`。  
> 本文替代 `2026-07-23-fog-routed-rgb-tir-dehazing-design.md` 中“仅由雾浓度产生路由”的设计；原文件保留作历史记录。

## 1. 核心问题

输入是含雾 RGB `I_rgb` 与配准 TIR `I_tir`，输出是一张清晰 RGB 图像。测试时只输入这两张图；不输入清晰 RGB、深度图、雾气 GT 或任何路由掩码。

HDE 输出连续雾气浓度 `M=1-T`。它描述“一个区域的雾有多重”，但不等于补全--融合路由图。

路由图描述的是：**一个具有局部上下文的区域中，RGB 是否已经完全失效，是否还应把本地 RGB 特征当作可靠信息使用。**

```text
R = 0：融合。RGB 仍有颜色、纹理或可辨识信息，保留 RGB，并以 TIR 辅助恢复。
R = 1：补全。RGB 的颜色、纹理和可辨识信息都已被浓雾遮蔽，丢弃本地 RGB 特征。
```

## 2. 路由判据

训练时，补全路由的真值直接由加雾过程的最终浮点透射率定义：

```text
Completion_Mask_GT(x) = 1[T_final(x) ≤ 0.05]
```

其中 `1` 表示补全，`0` 表示融合。它表示 RGB 的直达透射率不超过 5%，即加雾物理过程已使该位置的本地 RGB 信息近乎完全失效。掩码必须在生成 `hazy` 与 `M_GT` 的同一次前向中、从未量化的 `T_final` 保存；磁盘中的 PNG 仅是其二值编码。

**TIR 是否存在局部结构不是“是否补全”的条件。** 它只决定补全分支采用哪种恢复方式。因此，`mask_GT` 不由 TIR 边缘或 RGB--TIR 差异启发式构造，而是来自已知的真实雾场。

因此，以下情况都必须融合：

- 整图薄雾，但 RGB 仍有颜色、纹理或任何有价值的信息；
- 高雾但 RGB 尚未完全失效；
- 天空、均匀墙面等 RGB/TIR 都平坦、但并非浓雾遮蔽的区域。

而对于极浓雾：即使 RGB 与 TIR 在局部都没有明显轮廓，只要 `T_final ≤ 0.05`，仍然走补全。此时模型不能宣称恢复不存在的真实细节，只能输出由周围场景上下文支持的、视觉上平滑合理的结果。

## 3. 网络结构

### 3.1 HDE：连续雾气先验

现有 HDE 网络结构不修改。它从 `(I_rgb, I_tir)` 输出雾气浓度 `M`、RGB/TIR 特征、TIR 结构特征和跨模态结构差异特征。

数据目录名虽然是 `Transmission_Map_GT`，其中当前生成内容实际是 `M=1-T`。训练配置必须按 `density` 语义读取，不能再次反相。

### 3.2 信息失效路由器

主网络中新建路由器，读取 `M`、纯 RGB 编码特征、TIR 特征与 RGB--TIR 差异特征，输出：

```text
p_fog       ：浓雾证据，随 M 增大而不减
p_rgb_fail  ：RGB 颜色、纹理和轮廓均失效的证据
r_soft      ：连续补全倾向
R_hat       ：测试时使用的二值路由图
```

概念上：

```text
r_soft = p_fog × p_rgb_fail
R_hat = 1[r_soft >= 0.5]
```

其中仅以最终的 `r_soft` 接受 `Completion_Mask_GT` 监督；`p_fog` 与 `p_rgb_fail` 是路由器的内部可解释证据，不单独设置标签。RGB--TIR 的差异是判断 RGB 是否“因雾失效”的辅助证据：当 RGB 平坦而 TIR 仍能提供不同的信息时，它增强 `p_rgb_fail`；但模态差异大本身不能触发补全。

`0.5` 只是网络概率的二值输出分界，不是手工设置的雾气浓度阈值。

### 3.3 补全分支的两种内部状态

路由仍然只有二值的“融合/补全”，没有第三张路由图；但是补全分支内部必须区分：

```text
1. TIR 有结构：
   TIR 局部轮廓作为几何骨架，恢复对应的 RGB 外观。

2. TIR 无局部结构：
   不让失效 RGB 回流，也不伪造边缘；
   使用补全区域外的可靠上下文、全局场景特征和解码器先验，生成平滑合理的低频 RGB 外观。
```

这解决了极浓雾团内部“RGB 与 TIR 局部都平坦”的情况：它仍被路由到补全，而不是被错误当作融合；只是该区域没有可恢复的局部几何细节。

### 3.4 融合与硬补全

- **融合分支（`R=0`）**：输入 RGB 与 TIR。RGB 保留颜色、材质与可见纹理，TIR 用于结构辅助。
- **补全分支（`R=1`）**：不允许本地 RGB 特征通过残差、跳连或注意力键值进入；它使用 TIR、可靠区域上下文和解码器先验。
- 两条分支在特征层进入同一个共享 RGB 解码器；不是先得到两张图再做掩码拼接。

## 4. 物理 Completion Mask GT 监督的训练方式

不构造、不保存、不使用旧的 `Auto_Route_GT`。取而代之的是，训练数据由加雾生成器同步保存物理 `Completion_Mask_GT`；它不是从 `M + TIR` 边缘推测的伪标签，而是最终浮点透射率的确定性函数：

```text
Completion_Mask_GT = 1[T_final ≤ 0.05]
```

对预测路由倾向 `r_soft` 施加二元路由监督：

```text
L_route = BCE(r_soft, Completion_Mask_GT)
```

若实际训练中观察到正负像素显著失衡，可将该项替换为加权 BCE；这一调整只改变样本权重，不改变掩码的物理语义或路由定义。清晰 RGB `J` 仅用于最终去雾结果的重建监督，不参与测试阶段。

总目标保持三部分：

```text
L = L_rec + lambda_density × L_density + lambda_route × L_route
```

- `L_rec`：最终去雾图与清晰 RGB 的重建误差；
- `L_density`：HDE 的 `M` 与 `M_GT` 的监督；
- `L_route`：预测路由 `r_soft` 与物理 `Completion_Mask_GT` 的二元监督损失。

不使用旧的 `Auto_Route_GT`、在线反事实偏好损失、额外二值化损失、独立边界损失或多套区域重建损失。

## 5. 数据与测试

训练使用：清晰 RGB、含雾 RGB、配准 TIR、`M_GT` 与 `Completion_Mask_GT`，以及原有的 `mist`、`middle`、`dense`、`local_extreme` 四类雾。

测试只执行：

```text
(含雾 RGB, TIR) → HDE M → 路由 R_hat → 融合/补全 → 去雾 RGB
```

测试时保存 `M`、`r_soft`、`R_hat` 和去雾结果。路由图审核重点是：极浓雾团内部应整体偏向补全；其中 TIR 有结构的部分恢复轮廓，无结构部分保持平滑合理，而不是继续相信已经失效的 RGB。

## 6. 与上一版的差异

| 上一版 | 当前版 |
|---|---|
| `TIR 有结构` 是补全的必要条件 | TIR 结构只决定补全方式，不决定是否补全 |
| 自动生成 `Auto_Route_GT` 并用 BCE 监督 | 加雾过程同步生成物理 `Completion_Mask_GT`，并直接监督路由 |
| TIR 无结构的浓雾区会落入融合 | 仍走补全，使用上下文/先验平滑恢复 |
| 路由标签由模态启发式离线确定 | 路由真值由最终浮点透射率 `T_final ≤ 0.05` 确定 |

## 7. 实施边界

- 不修改 HDE 单独验证代码；
- 不修改旧主模型文件；新建 V2 实现；
- 不使用清晰 RGB 进行测试；
- 不创建或使用旧的 `Auto_Route_GT`；训练时只读取由生成器同步保存的物理 `Completion_Mask_GT`；
- 在实现前先为“`mask_GT` 路由监督与受控补全”设计最小可验证单元测试，确认掩码与同次 `T_final` 严格一致，并确认补全分支在 `R=1` 时没有本地 RGB 特征泄漏。
